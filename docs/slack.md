## Chat with Moyai in Slack

Channel and DM threads show Slack’s native **“Moyai is working…”** indicator instead of an eyes-only acknowledgment. It reflects the session phase (starting, working, saving, waiting for approval/key, or coordinating agents), refreshes every minute during long work, and clears on completion, stopping, or pausing. Slack expires an abandoned indicator after two minutes. State is reconciled after restart; temporary status failures are safe to retry without replaying the agent or its answers. Web follow-ups in linked sessions also restore the indicator. A top-level DM opens a new thread for its working indicator and replies. Session links use a compact footer below each answer.

Markdown tables in completed answers are sent as native [Block Kit table blocks](https://docs.slack.dev/reference/block-kit/blocks/table-block/). Columns wrap and preserve Markdown alignment; cells use literal text. Large tables split across messages with repeated headers (100 rows and 10,000 cell characters per table). Tables wider than 20 columns or with an oversized individual row use the existing text fallback. Table recognition uses `markdown-it-py` with its table rule enabled ([upstream source](https://github.com/executablebooks/markdown-it-py/blob/master/markdown_it/rules_block/table.py)); source maps preserve surrounding text. Fenced/indented code and tables nested in lists or blockquotes remain text. Table payloads are saved in the durable outbox alongside notification text, and use the same thread routing and delivery protections as other answers.

This uses AgentChat’s optional `set_status` API with Moyai’s persisted session state. Standalone SDK apps can use `async with context.working()` for refresh and cleanup within a handler. Existing Slack `chat:write` / `assistant:write` permissions suffice; no new scopes are requested.

PR handoffs add a LiteLLM card with the official train, a violet border, and **View PR**, **Review changes**, and **Open Moyai session** links. Slack controls the typography and native button styling. Cards use saved GitHub publication receipts from the session or its direct child agents, selected by the verified PR URL in the answer; an arbitrary link in model output cannot create a card. Plain answers keep their existing presentation.

Secure access requests name the required credential (for example, **VERCEL_TOKEN**) and let the original requester choose **Organization**, **Personal**, or **Session only**. The same card then shows the selected scope and a **Provide Secret** button that opens that exact request in Moyai's secure form. The form requires sign-in and enforces its existing permissions, including administrator access for organization secrets. Slack records only the scope preference; credential values never pass through Slack. Requests from child agents use the parent thread and link to the child's form. Reopened requests reset the choice, and older buttons cannot change the new request.

Enable **Interactivity & Shortcuts** in the Slack app and set its request URL to `PUBLIC_URL/hooks/slack/interactions`. Moyai verifies Slack's signature and the saved thread, installation, requester, and request generation before accepting a choice. Cards use the existing `chat:write` permission; deploying this code does not change live Slack settings or scopes. A known card is updated in place after a scope change, transient update failure, or restart; an initial send with an uncertain result is not posted again automatically. Pending cards skipped while the connection or thread is paused resume when it becomes available again.

In an already connected Slack thread or DM, the application also delivers at most one saved video and one screenshot whose exact capture paths appear in a completed answer. This also supports an explicit screenshot or recording follow-up without a new PR. It never picks the session's latest capture automatically or sends to a destination supplied by the agent. Media and cards use AgentChat's optional file-upload and rich-reply capabilities through the existing durable answer queue and its pause, connection-policy, and uncertain-delivery protections. Authenticated Moyai capture/session links remain available when native uploads are unavailable; ambiguous Slack delivery is not retried automatically.

Markdown file links in replies, such as `[dry-run details](/workspace/nightly-preflight/cutover-status.md)`, become Slack-native links to that session's saved file viewer. Inline filenames such as `report.md` also become links; fenced code examples stay unchanged. The viewer opens the latest saved file with a Markdown preview and Download button, and Google sign-in preserves the file destination. Missing or ambiguous references show an explanation and the available files. These links require normal Moyai access and do not upload the document to Slack or change old messages. Run `uv run python scripts/slack_file_links_demo.py` for a local demonstration at `http://127.0.0.1:8798/demo` using synthetic data and no live Slack writes.

Native media uploads require the bot's `files:write` grant. Older Slack installations need a one-time reinstall/reconnect after that scope is approved; cards use the existing `chat:write` grant. This code change does not alter live app permissions. Uploaded copies become visible to the connected Slack conversation's participants, while Moyai originals retain their authenticated access. Web sessions without a Slack binding gain no Slack destination.

Moyai uses [BerriAI AgentChat](https://github.com/BerriAI/agentchat), pinned to `6018987c22dd8424e4db0b780a2342239d800a61`, for normalized messages, conversation locks, handler dispatch, rich replies, and file uploads. The media capability is introduced in [AgentChat PR #11](https://github.com/BerriAI/agentchat/pull/11). Its stock Slack adapter uses Socket Mode; Moyai keeps its signed HTTP event endpoint. Our public Channel/State adapter preserves the existing signed HTTP webhook, rotating OAuth credentials, SQLite receipts, saved sessions, and durable reply outbox. No Socket Mode app token is required. AgentChat does not grant Slack permissions; an administrator still installs the scopes and event subscriptions below.

Install the dedicated **Moyai** Slack app with bot scopes `app_mentions:read`, `chat:write`, `im:write`, `files:write`, `channels:history`, `groups:history`, `im:history`, `reactions:write`, and `assistant:write`, subscribe to the `app_mention`, `message.channels`, `message.groups`, and `message.im` events, and set its request URL to `PUBLIC_URL/hooks/slack/events`. Keep the [user OAuth scopes](integrations.md#connect-the-apps) for conversation search; bot and user credentials are separate. Configure `SLACK_SIGNING_SECRET`, `SLACK_BOT_ENABLED=true`, and `SLACK_SESSION_USERS` as comma-separated Slack user IDs or `*` for all members of the installed workspace. Set `SLACK_THREAD_CHAT_ENABLED=true` and `SLACK_DM_ENABLED=true` (the defaults). Enable App Home’s Messages tab and allow users to send messages to the app. Enable the **Agent experience** under Slack app settings → Agents for the native AGENT badge and panel. Reinstall/reconnect Slack after adding scopes. The live BerriAI installation permits workspace members.

Invite the bot to a channel and mention **@Moyai** followed by a task. Moyai shows a native working indicator, then posts its answer in the originating thread with a compact link to the web session. Routine acknowledgment and periodic progress messages are suppressed; explicit status commands, failures, and approval requests still receive a response. Reply in that thread without another mention to continue the same saved conversation and files. Bot messages, edits/deletes, unrelated threads, and externally shared channel events are ignored. A message addressed first to another person or agent is ignored even when Moyai is mentioned later as the subject, such as “@OtherAgent what is @Moyai?” Explicitly addressing Moyai among adjacent initial mentions still works. Attachments are identified as unread; their contents are not ingested automatically.

Direct-message **Moyai** to start without a mention. Each top-level message starts a new saved session. Moyai replies in that message’s thread; reply there to reuse its conversation and files. A new message outside the thread starts fresh, just like a new channel mention. Model and stop/sleep/wake/status commands apply to the thread where they are sent. Existing sessions remain available in Moyai and through replies to their original root; their accumulated history is not split or copied into new sessions. A DM begins with the current request and saved session history, without importing older DMs through the shared search account. One-to-one DMs are supported; group DMs are ignored. Each DM is bound to its original Slack sender, and each turn keeps that sender’s spend attribution. **DM sessions are also visible to signed-in BerriAI teammates in the web app.** The first answer and Connections page explain this shared visibility. Slack’s Agent panel threads use the same session and reply routing.

Tasks use enabled organization connections. Everyone with access to the Slack thread can see both new inputs sent from its linked web session and the agent’s answers. Web inputs are posted by the bot with the authenticated sender’s name/email and a “via Moyai web” label; the bot never impersonates their Slack account. The web composer shows this sharing state. All enabled connected-app tools run without a per-use approval step in Slack sessions, under the same connection policies as web sessions.

Send `stop` to stop the response and cancel queued follow-ups; `sleep` also pauses listening and automatic answers in that thread. Use `wake` or a new direct mention to resume. `status` reports the session state. These commands must be the entire message. Pausing the organization Slack connection disables thread intake and pending replies.

Inbound receipts, working-status reconciliation, and the outbound reply queue are durable. Pending acknowledgment reactions from older releases remain bound to their accepted message timestamps; failures to react do not block answers. Pending pre-upgrade acknowledgment/progress messages are skipped on startup. Duplicate event IDs or paired mention/message events cannot create duplicate turns. Answers are bounded, formatted for Slack, and prevented from triggering user/channel mentions. An uncertain Slack delivery is not automatically retried; the answer remains in the web app. Rollout never posts historical answers: older threads are attached only after a new explicit mention. Answers completed while a thread is asleep are not backfilled on wake. New web inputs are saved atomically with their outbound chunks only while the Slack binding is enabled and awake. Existing web messages and inputs typed while sharing is paused are never backfilled. Duplicate submissions reuse their original queue entries, and long inputs preserve the saved text across ordered chunks. Mirrored bot posts do not start a second agent turn.

Before agent execution, Moyai reads only the addressed Slack thread through the **user OAuth** connection. A new top-level mention starts with that message alone; it never imports neighboring channel discussions. A mention inside an existing thread captures its root and replies through the mention timestamp (up to three pages, retaining at most 50 messages). Context is bounded to 24,000 text characters, with at most 3,000 per message. Truncation, missing context, and unread attachments are explicitly reported. Messages from other threads, later messages and Moyai’s own replies are excluded. The session shows the source link and included messages. Imported Slack content is labeled as untrusted reference data, separate from the current request. Older channel-wide snapshots are filtered on read to retain only the addressed message; already saved agent replies and sandbox conversation history are not rewritten.

Context retrieval runs in the background so Slack acknowledgement does not wait for history requests. The session starts only after context is ready or its failure has been recorded. Captured context is persisted, reused for follow-ups, and not fetched again on duplicate delivery. Unfinished agent work is still interrupted on restart, never silently replayed. Sessions created before this update are labeled as older sessions without automatically captured context; use a new mention for the new behavior.
